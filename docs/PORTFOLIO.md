# Bento portfolio

The portfolio is generated by Astro at `/` (Spanish) and `/en/` (English). It has no React hydration on these two routes. Existing post pages and legacy components remain available.

## Editing content

- `src/data/portfolio.ts`: provisional headings, descriptions, CV-based experience, case studies, technology groups and contact links. Keep Spanish and English entries aligned.
- Set `identity.photo` to an approved asset in `public/` (for example `/img/profile.webp`). An anonymous placeholder is rendered until then.
- `src/styles/portfolio.css`: semantic colors, light/dark themes, responsive layout and reduced-motion behavior.
- `src/components/portfolio/`: individual page sections.
- `src/layouts/PortfolioLayout.astro`: centered desktop navigation, language links and persisted theme preference. Small screens place navigation on a separate centered row.

The three featured case studies describe work from the CV. Their details expand locally; public repository and demo links remain pending confirmation. Project art is illustrative CSS, not screenshots of delivered systems. The historical project collection remains in the repository for later evaluation.

## Local commands

```sh
npm ci
npm run dev -- --host localhost
npm run check:portfolio
npm run build
```

`check:portfolio` checks the new page and its imports. The full `npm run check` currently reports 13 errors in unchanged legacy files: `src/components/shared/sidebar.astro` (12) and `src/pages/posts/[slug].astro` (1). These are outside the redesign scope. The existing `SITE_URL` used by the sitemap is still the template domain; replace it when the real deployment URL is confirmed.
